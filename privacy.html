Buffalo Pixel Publisher

Privacy Notice

Effective date: November 3, 2026

This notice describes how the Buffalo Pixel team handles information in Buffalo Pixel Publisher, a local tool used only for Buffalo Pixel's own publishing workflow. The tool is not currently offered as a public service. The Buffalo Pixel team is the operator responsible for the locally handled information described here.

1. Information handled

  • Account and authorization data: TikTok account identifier (Open ID), access token, and any basic account information returned by TikTok's API. The local TikTok adapter reads the access token and Open ID from a local credentials file.
  • Publishing content and settings: the video file selected for a job, caption, visibility and interaction choices, and other post settings entered in the publishing manifest.
  • Job records: account and platform identifiers, a video fingerprint and file size, scheduled time, job state, platform post identifier or URL when returned, and status notes.

2. How information is used and shared

The information is used to authorize API requests, submit the selected content and settings to the chosen platform, avoid duplicate jobs, and show upload status. For TikTok publishing, the selected video and post details are transmitted to TikTok. The tool does not send video files to a Buffalo Pixel-operated hosting server. GitHub Pages hosts this notice and may process ordinary web access logs under GitHub's own privacy terms. The tool does not intentionally sell personal information or use it for advertising.

3. Storage and retention

The tool runs locally. TikTok credentials are stored in a local JSON file at tools/social-publisher/secrets/tiktok.json; the operator must protect access to the computer and this file. Publishing jobs and their status are stored in the local SQLite database at tools/social-publisher/data/publisher.sqlite3. The current tool does not automatically delete that history; it remains until the operator deletes the database. The database is shared with other platform jobs, so deleting it also removes those records. Source video files remain wherever the operator stored them unless separately deleted. Backups made by the computer's owner may also retain local copies.

4. Security and access

Local credentials and job records are accessible to people who can access the computer or its files. The operator should restrict that access and should not share credential files. The tool does not claim that local files are encrypted. No storage or transmission method can be guaranteed completely secure.

5. Your choices and deletion requests

For this internal workflow, contact the operator at buffalopixelstudio@gmail.com to ask about locally held information. The operator can remove a specific job record or, on request, delete the local job database (which also removes job records for other platforms). The operator can delete the local TikTok credential file and the user can revoke access in TikTok account settings. The user can remove source videos from their own device. Copies already submitted to TikTok are controlled by TikTok and must be managed or deleted through TikTok. Requests will be handled under applicable data protection law.

6. Retention by TikTok and other services

When a post is submitted, TikTok processes the content and account data under its own terms and privacy notice. Buffalo Pixel does not control TikTok's retention or deletion practices. GitHub processes site visits according to its own policies.

7. Changes and contact

This notice will be updated if the tool's data practices materially change. For privacy questions or requests, contact buffalopixelstudio@gmail.com.
